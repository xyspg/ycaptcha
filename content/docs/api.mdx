All endpoints use `POST` with JSON request/response bodies. Base URL: `https://ycaptcha.xyspg.moe`

## POST /api/v0/captcha/challenge

Fetches a new image challenge. Called by the widget — you don't normally call this directly.

### Request

| Field | Type | Required | Description |
|---|---|---|---|
| `siteKey` | `string` | Yes | Your site's public key (`pk_...`) |

```json
{ "siteKey": "pk_aBcDeFgHiJkLmNoPqRsTuVwXyZ123456" }
```

### Response (200)

| Field | Type | Description |
|---|---|---|
| `sessionToken` | `string` | 64-character token identifying this challenge session |
| `prompt` | `string` | Puzzle instruction text (may contain `\|` separator) |
| `images` | `Array<{ id: string, url: string }>` | 9 images in randomized order |

```json
{
  "sessionToken": "aB3dEfGh...64chars",
  "prompt": "Select all images with|fire hydrants",
  "images": [
    { "id": "abc123", "url": "https://s3.ycaptcha.xyspg.moe/images/abc123.jpg" },
    ...
  ]
}
```

### Errors

| Status | Error | Cause |
|---|---|---|
| 400 | `"Missing siteKey"` | Missing or invalid request body |
| 404 | `"Invalid siteKey"` | No site matches the key |
| 404 | `"No puzzles configured for this site"` | Site exists but has no puzzles |

### Notes

- A random puzzle is selected from the site's pool on each call.
- Sessions expire 5 minutes after creation.
- Images are shuffled server-side with Fisher-Yates. The widget cannot distinguish correct from incorrect.
- Grid is always 9 images (3x3).

## POST /api/v0/captcha/verify

Submits image selections for verification. Called by the widget — you don't normally call this directly.

### Request

| Field | Type | Required | Description |
|---|---|---|---|
| `sessionToken` | `string` | Yes | Token from `/challenge` |
| `selectedIds` | `string[]` | Yes | Array of selected image IDs |

```json
{
  "sessionToken": "aB3dEfGh...64chars",
  "selectedIds": ["abc123", "ghi789"]
}
```

### Response — Pass (200)

```json
{ "success": true, "token": "aB3dEfGh...64chars" }
```

The `token` is the same as `sessionToken`. Pass it to your server for siteverify.

### Response — Fail (200)

```json
{ "success": false }
```

No `error` field means the user didn't select enough correct images. The widget auto-refreshes with a new challenge.

### Errors

| Status | Error | Cause |
|---|---|---|
| 400 | `"Missing sessionToken or selectedIds"` | Missing required fields |
| 400 | `"Invalid or expired session"` | Token not found, already used, or expired |
| 404 | `"Puzzle not found"` | Referenced puzzle no longer exists |

### Verification Logic

1. Session must exist, not be solved, and not be expired.
2. If all 9 images selected → automatic fail (anti-bot heuristic).
3. Count correct selections from `selectedIds`.
4. Threshold: `Math.ceil(correctImageIds.length * difficulty)`.
5. Pass if `correctCount >= threshold`.
6. On pass: session marked as `solved`, token returned.

Wrong selections (incorrect images) are **not penalized** — only the count of correct selections matters.

## POST /api/v0/captcha/siteverify

Verifies a token on your server. **This is the only endpoint your backend calls.**

**Requires your Secret Key — never call this from the browser.**

### Request

| Field | Type | Required | Description |
|---|---|---|---|
| `token` | `string` | Yes | Token from the widget's `postMessage` |
| `secretKey` | `string` | Yes | Your site's secret key (`sk_...`) |

```json
{
  "token": "aB3dEfGh...64chars",
  "secretKey": "sk_aBcDeFgHiJkLmNoPqRsTuVwXyZ123456"
}
```

### Response — Success (200)

```json
{ "success": true }
```

### Response — Failure (200)

All failures return HTTP 200 with `success: false` and an `error` field:

| Error | Meaning |
|---|---|
| `"Missing token or secretKey"` | Missing required fields (also 400) |
| `"Invalid token"` | Token not found — never issued, already consumed, or deleted |
| `"Invalid secretKey"` | Secret key doesn't match the site owning this puzzle |
| `"Challenge not solved"` | User never passed `/verify` |
| `"Token expired"` | 5-minute window has elapsed |

### Important

- **Tokens are single-use.** On success, the session row is deleted. Calling siteverify again returns `"Invalid token"`.
- The `secretKey` is verified by joining through the puzzle to its site — a token from one site cannot be validated with another site's key.
- Always check `result.success === true` explicitly. A 200 status alone does not mean success.
